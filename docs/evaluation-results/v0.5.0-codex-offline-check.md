## Implementation

- `scripts/run-codex-offline-check.mjs` exposes an offline-only API. It launches the repository's fixed `evaluation/tooling-fixtures/fake-codex.mjs` using the current hashed Node executable. Arbitrary executable/provider options, live mode, source-bearing phases, and direct CLI execution are rejected.
- Preflight requires explicit offline authorization, frozen tool/Prompt/workspace hashes, absolute non-symlink paths, separate empty HOME/CODEX_HOME/temp/evidence directories, and no ancestor or local client instructions. The source-free test case additionally requires an empty workspace and the exact probe Prompt.
- Prompt bytes travel through stdin with `shell: false` and the explicit `-` sentinel. Environment variables are constructed from an allowlist rather than copied from the parent. No real credential is used or injected.
- A reserved attempt record prevents reuse of the evidence directory after either success or failure. Bounded process execution retains stdout, stderr, final output, hashes, and the outcome; malformed, incomplete, duplicate, unknown, tool-bearing, failed, or mismatched source-free responses fail closed.
- Workspace snapshots include regular files, permissions, empty directories, and mock `.git` bytes. Negative writes are detected without repair. This checks hashing logic, not Git semantic correctness or OS-enforced write prevention.

The fake client has no network implementation. It generates deterministic local outputs and, in one case, launches a second Node process to inspect its inherited environment. Its test-only capture contains the allowlisted environment and synthetic Prompt, never a real authentication value. Test-owned temporary directories are removed by the test lifecycle; no retained Candidate or installation directory is touched.

The seven historical fixture outputs were already manually inspected for their seeded assertions; this correction does not reclassify those records or claim they used the new gate.

The preparer now uses a small Node test reporter to retain structured test events, including error causes, without adding dependencies. It checks the exact test file, names, count, pass/fail outcomes, `ERR_ASSERTION` cause for expected failures, and completed aggregate counts. Skipped, todo, missing, extra, malformed, and non-assertion results fail closed. Future preparation records include the reporter hash and validated test counts; the reporter and expectations stay outside model workspaces. Test stdout is now JSONL in newly generated evidence, not a rewrite of the old text evidence.

Commands retain stdout, stderr, exit status, signal, and launch-error metadata before result classification. Preparation failures retain the command data in `failure.json`. Test completion, rejection, and command failure all attempt Git and filesystem after snapshots independently; a failed capture is recorded and cannot be promoted to a pass. Mutated files are not repaired.
