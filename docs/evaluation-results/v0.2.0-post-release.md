## Deterministic Evidence Boundary

The temporary TypeScript fixture initially used an extensionless import. `node --test` stopped during ESM module resolution and did not reach the assertion. That failed command is not counted as behavior validation. A separate read-only expression evaluation confirmed the generated triple-slash URL.

The checked-in post-v0.2.0 fixture replaces that temporary harness with explicit `.ts` imports and a runnable Node 24 test. This improves future reproducibility but does not retroactively turn the earlier failed command into a passing test.

## Authentication and Provider Boundary

The successful Codex run used a locally configured custom Responses-compatible provider. A discarded attempt used `--ignore-user-config`, bypassed that provider, and called the official OpenAI endpoint with a provider-specific token; its `401` result is not a Skill failure and is excluded from runtime evidence. No endpoint, token, account identifier, private source, or sensitive payload is recorded here.

## Limitations

- The fixture measures recall for seeded findings, recommendation consistency, localized structure, and read-only behavior. It does not establish general precision or recall.
- Runtime evidence is scoped to the recorded clients, model path, fixture, and date.
- Cursor Desktop was not rerun.
- Claude Code remains `Cannot Verify`.
- No browser, WebView, Native bridge, device, backend, or production path was exercised.
