## Scope

The candidate adds checked-in synthetic fixtures, machine-readable semantic oracles, an isolated Git fixture preparer, and deterministic Vitest coverage. It does not change the core Skill, public modes, severity contract, read-only boundary, or output templates.

The authorized runtime input scope was limited to the synthetic repositories under `/private/tmp/fe-code-review-v021-*`. Cursor stayed within that fixture scope. The captured Codex trace additionally shows automatic reads from user-level Memory, so the Codex run is not treated as strictly fixture-isolated. The observed Memory excerpts contained review-tool and evaluation metadata plus local paths; the captured trace showed no business source, credentials, provider URL, or account identifier.

## Deep Design Oracle Correction

The initial Deep fixture expected `Redesign`. Runtime inspection showed that the safe repair is to remove the profile-owned token cache and reuse the existing `auth/session` owner. That reduces competing state ownership without requiring a new architecture, so `Simplify` is the stricter and more accurate decision under the Skill contract. The oracle and its deterministic test now require `Simplify`.
