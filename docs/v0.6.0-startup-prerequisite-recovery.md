# v0.6.0 Startup Prerequisite Recovery

## Finding

On 2026-09-17, offline inspection identifies a confirmed regression in the Gate B diagnostic profile generator: the exact-root data-read exception previously required and tested on this machine was omitted. The published v0.5.0 Skill is unaffected. The current entry-helper crash remains a failed runtime result; restoring a known policy prerequisite offline is not runtime acceptance.

The missing rule is:

```scheme
(allow file-read-data (literal "/"))
```

This permits opening or listing the root directory itself, including its entry names. It does not grant recursive content reads. Do not substitute `(subpath "/")`, grant all root read operations or import the complete Apple private profile.

## Termination Evidence

The installed system is macOS 15.2, build 24C101, with the 15.2 SDK. The inspected public/kernel SDK headers expose exit-reason storage but no verified symbolic mapping for namespace `0x23` in the bounded search. The secinit text stub provides exported names, not startup behavior or a cause.

Read-only arm64e disassembly of the current `/usr/lib/dyld` shows `_ignition_halt` preserving its input reason and passing `0x23` as the namespace to `_abort_with_reason`. `_boot_boot` calls `open("/")` and has a failure branch with the message `failed to open root directory` leading to `_ignition_halt`. The post-init boot specification contains reason 2 and flags `0x40`. Several ignition failure sites use the shared boot reason. Therefore code 2 cannot by itself identify one failed operation or be interpreted as errno 2.

This is a static match to a possible termination path, not the crashed process's call stack. The actual report has no usable backtrace, image list or errno. The additional report flags are not decoded here. Missing-root permission is now an evidence-supported explanation to verify after restoring the contract; the current SIGABRT cause and previous UE cause remain unconfirmed. Cryptex paths in Apple's profile are other startup context, not authorization to add broad cryptex reads.

## Offline Correction

Ignored `gate-b-startup-prerequisite-01` contains the evidence excerpts, binary addresses, verified historical artifacts, a small policy-restoration helper and thirteen passing tests. The helper accepts only the pinned failed entry baseline and appends the single exact root-data rule. The candidate retains every previous policy byte. The old helper, profiles, manifests, results and 165-file result history remain untouched.

The new tests require the exact addition and reject the unmodified deficient baseline, recursive root access, broader root read operations, duplicate exceptions, removal of network/file-read denial, extra temporary-write or home-read grants, full-profile imports, process-rule changes, extra cryptex access and input-baseline drift. These are string-contract tests for one frozen policy, not a general Seatbelt parser or runtime enforcement tests.

No native helper, sandbox policy, actual CLI/host, Guard, model/provider or process collector is launched. The historical native controls are reused without rerun. No credentials, installation, Git write or formal Skill change occurs. All current process observations remain from the previous runtime; this offline step does not refresh them.
