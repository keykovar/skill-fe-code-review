## Entry Points

The current repository's `scripts/validate-review-output.mjs` and package script retain the default contract and now support explicit v0.6.0 selection. `scripts/review-output-profile.mjs` is a compatibility entry forwarding to that same implementation:

```bash
node scripts/review-output-profile.mjs --mode quick --profile v0.6.0 --source-root /review evaluation/prototypes/origin-occurrence/integration-11-example-corrections-01/quick.en.md
```

The [revised local package](../.local-evaluation/v0.6.0-public-profile-package-02/package/README.md) contains the intended final path, `scripts/validate-review-output.mjs`. Run from that package directory:

```bash
node scripts/validate-review-output.mjs --mode quick --profile v0.6.0 --source-root /review examples/outputs/quick.en.md
```

`/review` is the declared root in these authored examples. For an actual linked report, independently supply its canonical absolute POSIX source root; the validator never infers it from the report or reads source files. Plain Coverage locations require no source root. Fix does not gain a Coverage ledger.

The facade and packaged entry both export:

```js
validateReviewOutput(markdown, mode); // Unchanged legacy JSON.
validateReviewOutput(markdown, mode, { profile: 'v0.6.0', sourceRoot: '/review' });
```

| Selected-profile field | Meaning |
| --- | --- |
| `valid` / `structurallyValid` | Selected structure and Origin/Reproduction grammar pass; not a verdict about code correctness |
| `metadataValid` | Field presence, state and observation-count grammar pass |
| `raw` | The unchanged legacy validator's result on the original report |
| `structure` | Structure check on the selected validation view; legacy projection may still show the reconciled missing-ID condition |
| `findings` | IDs, line numbers, kinds, origins and separate reproduction groups; no invented legacy IDs or pooled observations |
| `compatibility` | Coverage link, legacy Fix, status-emphasis and empty-marker handling recorded separately |
| `errors` | Remaining structure, field and presentation failures |
| `semanticStatus` / `reportAcceptance` | Always `Not Evaluated`; provenance, severity, totals, closure and recommendation meaning require evidence assessment |

CLI exit codes are **0** for valid structure/fields, **1** for an invalid report, and **2** for invocation/read errors. Unsupported profiles/options fail. `sourceRoot` is not silently accepted without the explicit profile. Reports are never rewritten. The API supports stdin/eval hosts without invoking the CLI. Direct CLI execution handles directory aliases, including macOS temporary paths and `--preserve-symlinks-main`.
