## Candidate Changes

- Every Finding and Fix verification item includes **Origin**: New, Amplified, Retained or Unknown relative to the declared comparison baseline.
- **Reproduction** distinguishes Observed, Not Run, Cannot Verify and Not Applicable. Completed observations use separate evidence-backed `n/N` groups by revision/environment. These are sample counts, not production occurrence probabilities or confidence estimates. Filling these fields does not require an additional test run.
- Checked Coverage links, explicit supported before/after outcomes, exact empty-section markers, numeric Fix tallies and consistent conclusion/final prerequisites complete the accepted output contract. Quick, Deep and Fix remain the three read-only modes.
- The public output validator offers an opt-in `v0.6.0` profile. Default API/CLI behavior remains compatible with the previous validator; structural validity does not prove that a finding is true or a fix is correct.
- Six bilingual authored examples supplement the four earlier examples. Frozen historical builders/baselines preserve reproduction of past candidates and their failures.

This is a minor version because the Skill requires additional finding fields. Users invoking the optional output validator select `--profile v0.6.0` explicitly; consumers of its default JSON receive the previous contract.
