## Implementation

The [probe script](../scripts/origin-occurrence-api-probe.mjs) reuses the existing [response parser](../scripts/origin-occurrence-api.mjs) and supports only a fixed source-free body. `prepare` is offline. `run` verifies the exact plan hash independently supplied by the operator, the current three script hashes, exact request bytes and an unused two-file inventory before accepting any credential. An altered endpoint with a correspondingly edited plan still fails against the previously approved plan hash. A fresh digest cannot relax the current fixed limits/body/tool hashes.

The transport uses Node's built-in `https.request`, with certificate validation, no shared agent, a bounded header parser and no retry/redirect/tool dispatcher. It requests uncompressed JSON, rejects unexpected encodings/content types and stops at the byte/deadline boundary. There are no client, browser, MCP or model-selected subprocesses. The recommended invocation below clears inherited process environment for the sender; it discovers no proxy, key or provider configuration and changes no system settings. A direct connection failure stops instead of switching transport.

The credential comes from stdin only. The CLI refuses an interactive echoed stdin, and accepts no key argument or environment-key lookup. No credential is written to the request body, command history or logs by this program. Known input buffers are cleared when consumed; this does not claim cryptographic erasure of JavaScript strings or operating-system memory. Errors are recorded by fixed categories, without copying exception text or request headers.

Result files are exclusively created, with directory mode 0700 and file mode 0600. A bounded partial body may be retained when transport fails; oversized chunks are not appended. A completed HTTP exchange is distinct from a completed model response. `dispatchAttempted` records a local attempt, not a proof that the provider received a request. Missing usage remains unavailable. No remote cancellation, billing-stop, OS-enforced immutability or Codex isolation claim is made.

## Compatibility Decision

An `Observable Pass` requires all of the following:

1. Successful HTTP status, supported completed Responses JSON, one assistant text message and no refusal/tool/unknown output, as checked by the existing parser.
2. The exact marker, allowing surrounding whitespace only.
3. Matching returned model, reasoning effort, empty tools, tool choice, background/store/truncation controls and output cap, with no returned prior response or conversation state.
4. Valid reported token usage with output count at or below the requested cap.

Missing control fields or usage cannot be treated as compliance. They produce `Cannot Verify` or envelope rejection; different values produce `Not Accepted`. No parameter is silently dropped, no model alias substituted, and no alternate API route tried. Provider-reported matches are observable compatibility evidence only. They cannot prove model identity, server-side logging/retention, hidden tools or cap enforcement. Stream behavior is checked through a completed JSON HTTP response, not an invented echoed `stream` field.

Even `Observable Pass` keeps `runtimeReady: false`, `sourceTransferAuthorized: false`, `codexAcceptance: Not Evaluated` and `reportAcceptance: Not Evaluated`. Its value is that a later separate decision can consider the first source-bearing request. It does not score Origin/Reproduction or a full review.
