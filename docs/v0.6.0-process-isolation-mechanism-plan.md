## Mechanism Decision Matrix

| Mechanism | Supported evidence | Limitation and decision |
| --- | --- | --- |
| `ps`, libproc process/child queries | Snapshots of processes visible at query time | Short-lived, reparented or regrouped descendants can be missed. Auxiliary pre/postflight only. |
| `kqueue` / `EVFILT_PROC` | Notifications for a registered, known PID, including fork/exec/exit | Darwin does not pass the child PID through `NOTE_FORK`; automatic descendant flags are unsupported. Events also coalesce. Known-child lifecycle aid only, not a complete process history. |
| Suspended native spawn plus known-PID registration | SDK defines suspended-start, setexec and close-on-exec flags | Definitions do not prove behavior. Can address root registration timing if tested; cannot repair unknown-descendant coverage. |
| Seatbelt `process-exec` / `process-fork` | Shipped system profile demonstrates operation/filter syntax | Exact initial-exec, spawn/fork, alias, thread and inheritance semantics are untested here. Selected only as a capability-test candidate. `sandbox-exec` is deprecated. |
| Endpoint Security native client | Fork child identity, exec identity, parent identity and sequence counters are documented | Requires entitlement, FDA and privileges; must handle event drops, muting and versioned identities. Availability is unverified. Not selected for this window. |
| `eslogger` | Documented notify-event collector | Requires super-user and FDA; suppresses its process group; output is explicitly not a stable API. Observation is not execution prevention. Do not start it. |
| `execsnoop` / DTrace | Documented exec tracing | Requires root; exec events alone do not establish complete fork/exit lineage. Not selected. |

`kqueue + ps` does not become complete by polling faster. A cooperative fixture can prove its own known children exited; that does not prove an opaque CLI had no other descendants. If a later collector is considered, it must start before the target, distinguish PID reuse/exec versions, cover fork/exec/exit through reparenting/group changes, account for mute/filter rules and sequence gaps, and confirm complete closure. Any missing event or unknown child fails acceptance. Raw argv/environment or unrelated process events must not be persisted.

## Actual Host Interface

Static host strings identify Code Mode gRPC/session modules and execution-limit errors. They do not establish an externally supported launch protocol or self-test command. This inspection and the bounded official-document search did not verify an interface that can run the required actual-host controls without model-selected code. No `--stdio`, `--socket`, guessed request schema or invented self-test flag is adopted.

The official [Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security) page scopes sandbox mode to model-generated commands and explicitly excludes the client's model/authentication requests from the command network proxy. It also states that asynchronous monitoring does not replace sandboxing, permissions or result review. These product controls cannot substitute for the separate outer CLI/host policy required by this experiment. The retained excerpts come from a truncated retrieval, not a complete documentation audit.

Actual startup/control access remains a separate missing input. Do not disable the selected host, change the frozen tool/request surface, or send a model request to discover it. A future interface-discovery launch, if justified by supported usage, requires its own bounded source-free manifest first.

## Next Native Capability Window

Prepare a fresh ignored directory containing a small C helper and a trusted supervisor. Compile against the already available SDK, inspect the source and freeze the helper/compiler/profile hashes before executing it. No dependency installation is needed. Use two candidate process policies: an exact-executable allowlist with process creation denied, and a separately labelled fork-allowed diagnostic only for the inheritance controls. Neither policy is adopted for the actual CLI by these tests.

| ID | Frozen capability question | Required observations |
| --- | --- | --- |
| B-N01 | Can the initial exact helper exec and create/join a thread under the process-denied candidate? | Initial exec outcome, thread completion, known PID and confirmed exit/output closure. A startup denial is a failed candidate, not permission to broaden the profile. |
| B-N02 | What happens to `fork`, ordinary `posix_spawn`, `execve` and `POSIX_SPAWN_SETEXEC`? | Separate return/errno and child/target markers for each operation against exact allowed and unlisted fixture targets. No target loops, network or uncontrolled follow-on spawn; every unexpected child exits immediately and is reaped. |
| B-N03 | How do an exact path, a symlink to it and alternate argv0 values behave? | Distinguish policy path resolution from helper dispatch. Pin both targets and alias metadata; an allowed alias is not proof its alternate CLI role is acceptable. All aliases are synthetic, not the real CLI. |
| B-N04 | Do permitted fixture descendants retain file/descriptor restrictions through fork, exec and group changes? | Separate fork-allowed diagnostic; fixed shallow children with bounded lifetime and direct supervisor control. Own public canary read/write succeeds; foreign public canary read/write fails; undeclared pipe identity is absent. Require all known children reaped. This is cooperative-fixture evidence only. |

The native fixture's default network policy remains deny-all; no listener or connection is needed for these first capability questions. Existing actual-role network tests remain retained and actual-descendant network controls remain pending. Do not quietly count their reuse as fresh child-process network evidence.

Freeze exact subcases/argv/paths before running, with no automatically expanded matrix. Use an outer trusted supervisor and one Seatbelt application per role; do not repeat the known nested-sandbox failure. Keep a 6-second per-case and 30-second total envelope, including bounded TERM/KILL/output closure, 64 KiB per-stream and 512 KiB aggregate evidence (128 KiB reserved for closure). Use fresh task-specific directories and a minimal environment; no personal HOME/config/credentials. Retain a fresh owned-process/UE preflight immediately before execution. Unconfirmed exit, overflow, timeout, unexpected access or untracked child stops the window without automatic retry.

The next action is to implement/compile this fixture and freeze its executable manifest. No native capability case is executed by this document or its static inspector. There is no current launch permission for real keys, providers or source-bearing reviews.

## Acceptance And Remaining Blockers

Capability results may reject a candidate early; they cannot alone pass Gate B. A no-fork policy is useful only if verified semantics also block other process-creation paths and the selected actual CLI/host still works unchanged. If host startup requires children, retain that requirement and leave descendant observation unresolved; do not substitute a witness or disabled-host run.

Gate B still requires actual CLI/host controls for startup, scratch, allowed/denied files and sockets, credential/config descriptor exclusion, aliases, inherited restrictions and descendant closure. No adequate complete-descendant collector or actual-host control interface is currently verified. Gate C and live runtime readiness remain blocked until those assertions have evidence. This preparation does not refresh current OS process/port state.
