## Smallest Diagnostic

Proposed ID: `B-S01-entry-baseline`. Its only question is whether a new minimal public helper can emit its entry marker and exit under the retained file restrictions and deny-all network policy, without explicit process-denial rules. This is a prerequisite observation, not an A/B comparison with the old helper.

The new helper has one operation and no configurable mode. It does not install signal handlers, scan descriptors, create threads/children, open files or perform network operations. The intended source is:

```c
#include <unistd.h>

int main(void) {
    static const char marker[] = "FE_ENTRY_01\n";
    ssize_t written = write(STDOUT_FILENO, marker, sizeof(marker) - 1);
    _exit(written == (ssize_t)(sizeof(marker) - 1) ? 0 : 74);
}
```

Use a fresh helper, policy, empty working directory and exclusive evidence directory. Derive the diagnostic profile from the retained baseline: preserve `(deny network*)`, file-read/file-write denial and required system-library/device exceptions; replace the old fixture executable grants with the single new exact executable and map only necessary ancestor/cwd metadata paths. Record every path delta. Do not add shell/application-directory grants or modify an accepted policy. The process-default baseline is not a security-isolation policy.

Use the existing `runBoundedControl` directly from one trusted Node supervisor to `sandbox-exec` and the helper. Remove the intermediate Python condition adapter from this new diagnostic only. Pin the supervisor dependency and evidence-store hashes. Check frozen inputs before starting the single child timer. Capture the child PID/process group and native stdout/stderr directly, with no shell. Changing the helper and supervisor reduces the experiment; it prevents attributing a different result solely to one old policy rule.

The future runtime manifest must freeze all absolute paths, executable/compiler hashes, the exact argv and policy, clean environment and byte limits. The environment contains only fixed `PATH`, locale/timezone and fresh empty task-specific HOME/TMPDIR paths if needed; never inherit user configuration or credentials. No runtime manifest or launch permission is created by this design.

## Bounds And Decisions

One target launch maximum; no second condition or retry. Reuse the bounded controller with a 4,000 ms child deadline, 250 ms TERM grace, 750 ms KILL grace and 100 ms output-close grace. At most one TERM and one KILL are attempted while the owned child is unexited; log signal failures without extra recovery loops. Cap each target stream at 4 KiB and use the retained 512 KiB evidence budget with 128 KiB reserved for closure. A 10-second runtime observation envelope includes bounded pre/postflight and result persistence; expire before launch if less than the child/closure/postflight budget remains. Preparation hashes are outside this runtime envelope and rechecked immediately before it.

These values bound the observer's wait, not the kernel's ability to terminate a process. A minimal helper can still hang. Child exit/output closure and a fresh identity-aware process/UE snapshot are required independently. `ps` is an auxiliary snapshot, never complete descendant observation. If bounded postflight cannot finish, persist `incomplete` without claiming a clean system.

| Observation | Classification and action |
| --- | --- |
| Exact `FE_ENTRY_01\n`, empty stderr, status 0, no signal/error/stop reason, confirmed child exit and output closure, clean postflight and unchanged inputs | `entry-baseline-complete`; end the window. This proves only this helper's entry/exit. |
| No marker, but a confirmed nonzero/signal exit and fully closed streams with clean postflight | `closed-startup-failure`; retain failure and stop. It does not identify a policy cause or permit a strict run. |
| Marker with nonzero exit, extra/truncated output or any deadline/cancellation | Failed/incomplete diagnostic; retain the marker as partial evidence and stop. A marker alone is never a pass. |
| Missing exit/closure, process-identity uncertainty, residual/UE, failed inspection, input drift or evidence overflow | `incomplete`; stop all runtime progression. Do not retry, extend the deadline or repeat signals automatically. |

Offline adjudicator tests must cover the valid receipt and independent negative cases for missing/extra marker, nonzero exit, stderr, signal, status-0-plus-deadline, unconfirmed exit, unclosed output, residual/UE, failed inspection, identity mismatch, input drift and overflow. Synthetic receipts and fake lifecycle events must not start the helper, sandbox, CLI or network. Reuse unchanged controller tests as historical evidence; add only targeted tests for the new receipt and direct-launch wiring.

## Next Steps And Limits

Next implement and compile the entry helper, inspect compiler output without running it, implement the one-launch supervisor/adjudicator and run offline tests. Freeze a new executable manifest only after those checks pass. Runtime execution remains a later bounded action; it cannot follow automatically from compilation or a previous window's authorization.

Only a completed baseline can justify considering a separately planned strict entry control. Descriptor and thread controls, old baseline, remaining twelve native cases and actual CLI/host controls do not auto-resume. Any later comparison needs identical new helper/supervisor inputs and explicit policy deltas. No result from this minimal probe alone accepts process isolation, root cause, review quality or live-provider readiness.

This work needs no new dependencies, real API key, provider/model request, private source, privileged collector, installation, Git write or stable Skill edit. Gate A's accepted 4 + 1 evidence is reused without rerun.
