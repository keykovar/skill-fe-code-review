# v0.6.0: 问题来源与复现观测

[v0.6.0 已于 2026-10-09 发布](https://github.com/keykovar/skill-fe-code-review/releases/tag/v0.6.0)，标记为 Latest。不可变 tag 指向提交 `f2dc57a4a983dd682055662b5ee75ebb28d464da`。tag 内的待发布文字保留打包时状态；本页同步实际发布结果，不移动 tag。

## 本次变化

- **问题来源 / Origin**：每条 Finding 和 Fix 问题验证项明确区分本次引入（New）、本次放大（Amplified）、历史遗留（Retained）和无法确定（Unknown），并说明相对哪个基线作出判断。
- **复现观测 / Reproduction**：区分已观测（Observed）、未执行（Not Run）、无法验证（Cannot Verify）和不适用（Not Applicable）。有执行证据时记录已完成失败次数/试验次数 `n/N`，修复前后、不同环境的观测分别保留。样本比例不是生产复现概率，也不要求为填写字段额外运行测试。
- **输出一致性**：明确受影响条件组合的修改前后结果，支持受限的本地 Coverage 链接，规范空问题段落和 Fix 数字汇总，并要求结论与最终建议列出一致的必要条件。
- **维护工具**：增加显式 `v0.6.0` 输出校验 profile 和六份中英文示例，保留默认 API/CLI 的旧返回契约；历史构建器使用冻结基线，保留过往失败及评测记录。

Quick、Deep、Fix 仍是三个审查模式，继续默认只读。Fix 仍聚焦既有问题关闭与修改引入的回归。Origin 不明或缺少执行观测，不会自动把已有静态证据支持的修复判为无法关闭。

## 使用与兼容

普通 Skill 使用者沿用原来的调用方式和安装路径。使用不可变 `v0.6.0` tag 的干净检出替换已安装的 `skills/fe-code-review`；Cursor 项目按适配器说明保留对应 routing rule。

维护者需要校验新字段时，显式选择 profile：

```bash
node "scripts/validate-review-output.mjs" --mode quick --profile v0.6.0 --source-root /review "examples/outputs/quick.zh-CN.md"
```

这里 `/review` 是示例报告的源码根目录。实际报告应使用独立确认的源码根目录；只有普通位置、没有 Coverage 链接的报告可以省略 `--source-root`。API 第三个参数为 `{ profile: 'v0.6.0', sourceRoot: '/review' }`。默认调用仍使用旧校验规则。

结构校验通过不代表问题真实、来源判断正确或修复已完成；`reportAcceptance` 始终为 `Not Evaluated`，语义验收仍需对照代码和证据。

普通 Markdown Skill 使用不要求 Node.js、Vitest 或 PyYAML。Git 用于仓库 diff；Node.js 仅用于可选上下文收集器和校验工具，Vitest 与 Python/PyYAML 用于维护者检查。
