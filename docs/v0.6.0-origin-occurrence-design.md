## Existing Behavior And Gap

The current [Skill](../skills/fe-code-review/SKILL.md) already requires before/after analysis, reporting material retained defects in modified decision blocks, concrete triggers, impact, root cause, suggested repairs, and verification. It does not require fixed origin or reproduction-observation fields. Do not describe the current release as lacking all regression analysis or as already providing the proposed fields.

The change addresses repeated user requests for explicit attribution and occurrence evidence. It is not yet supported by a new model-quality measurement. Its value and cost must be tested before promotion; additional fields alone do not prove a better review.

## Minimal Output Delta

Add two compact fields to each Quick/Deep Finding and each Fix Issue Verification or New Regression entry. Reuse existing scope, trigger, root-cause, current-evidence, and verification fields; add no top-level section or mandatory JSON report.

| Chinese field | English field | Required content |
| --- | --- | --- |
| 问题来源 | Origin | One origin label, the comparison anchor, and a short before/after causal basis or the specific missing evidence. |
| 复现观测 | Reproduction | One observation state, observed counts only when supported, and the environment or evidence reference needed to interpret it. |

The existing trigger field describes the necessary input/state and action order. The existing root-cause field explains how that trigger reaches the defective branch or consumer and produces the impact. Reference that explanation instead of repeating it in both new fields. Fix can use its existing before/after behavior and current-evidence fields for the same purpose.

For no-finding reports, retain the current empty-section wording and applicable `Keep` decision; do not manufacture Finding entries or empty origin/reproduction sections. Maintain the current single-line Changed-Condition Coverage grammar without adding these fields to ledger lines.

## Origin Contract

Origin is relative to the selected review baseline, not a claim about the first-ever introducing commit or its author. Freeze the requested comparison once: for example, HEAD versus the selected working tree, HEAD versus index for staged-only review, or the declared branch-range baseline. Do not silently substitute a different baseline or re-run Git history merely to fill this field.

| Label | Chinese rendering | Evidence required |
| --- | --- | --- |
| New | New：本次引入 | The defect is absent in the selected baseline under the applicable contract, and the reviewed change introduces the failing path or removes required behavior. |
| Amplified | Amplified：本次放大 | The defect already exists, but a concrete change expands its reachable inputs, affected callers, persistence, or demonstrated impact. Identify both the old defect and the changed exposure; do not infer a frequency increase without data. |
| Retained | Retained：历史遗留 | Baseline and current evidence show the same material defect without a demonstrated amplification. Include it only when it lies within the selected changed decision block, directly affected contract, or previous Finding scope. |
| Unknown | Unknown：无法确定 | Current evidence may establish an actionable defect, but the relevant baseline or causal comparison is unavailable or inconclusive. Name the gap; do not guess New from changed lines or Retained from old-looking code. |

Renaming, relocation, line age, a newly added test, or a newly observed error does not itself establish New. If old and new defects require independently repairable changes, preserve separate Findings rather than merging them under Amplified.

Unknown origin is not a severity, a new Finding, or an automatic block on closure. Retained origin is not a reason to hide an in-scope material defect. Neither label overrides the existing severity or recommendation contract. An unrelated historical issue does not justify expanding Quick/Fix into a repository-wide audit.

## Reproduction Contract

| State | Chinese rendering | Meaning |
| --- | --- | --- |
| Observed | Observed：已观测 | An executed check or explicitly supplied usable record supports `n/N`: n observed failures among N valid completed trials for the same defined scenario and environment. Include the source and relevant revision. |
| Not Run | Not Run：未执行 | No usable execution observation exists. Explain the static trigger and its evidence; do not invent a denominator or claim a runtime reproduction. |
| Cannot Verify | Cannot Verify：无法验证 | Required runtime observation could not be completed or its environment, state, or evidence cannot be matched. State what is missing; preserve usable observations separately. |
| Not Applicable | Not Applicable：不适用 | A non-runtime maintenance/design issue has no meaningful failure-trial count. State the concrete maintenance cost instead of fabricating a reproduction rate. |

For Observed, require integers `0 <= n <= N` and `N > 0`, a definition of failure, and a source that actually supports the counts. Test assertions, tool calls, users, requests, and complete scenario trials are different units; do not exchange them to produce a denominator. Setup failures, blocked commands, and interrupted attempts are not valid trials. Preserve their counts or limits separately rather than silently treating them as successful non-reproductions.

- `1/1` means one observation, not a guaranteed 100% occurrence rate. `0/3` means not observed in those three trials, not proof that the code is correct or that the issue is resolved.
- Keep different browsers, revisions, inputs, accounts, reset conditions, or concurrency schedules in separate observation groups. Do not sum incomparable groups into one attractive ratio.
- Distinguish static reachability, finding confidence, sample reproduction, and production occurrence. Static reasoning does not create an Observed result. An assertion failure supports only its exercised contract, not necessarily a browser or production outcome.
- Do not estimate numerical production probability or label a path statistically rare/common without representative evidence. This candidate standardizes observation counts, not a probability estimator. Production telemetry analysis is outside its scope and requires a separate request and authorized data access.
- Report a rare-looking but supported, reachable trigger when its demonstrated impact warrants a Finding. Describe the restrictive conditions rather than discarding the issue or lowering severity solely because it needs an unusual state. Purely hypothetical, unreachable, or unsupported conditions are not actionable Findings.
- Reconcile contrary evidence before finalizing. A valid reproduction that refutes the claimed causal path cannot be ignored by adding Unknown or Cannot Verify. Investigate within scope, narrow the claim, or withdraw it as the evidence requires.
- Do not run tests, repeat checks, start Playwright, access production, or install dependencies just to fill a count. Existing authorization and mode budgets remain the authority. A valid static review can say Not Run without pretending to be runtime acceptance.

## Mode And Legacy Behavior

Quick and Deep apply the two fields to each independently reported Blocking, Risk, and Improve Finding. Existing root-cause and verification detail remains mandatory where currently required. Origins do not change ID ordering or the Blocking proof pass. Improve-only, non-runtime suggestions normally use Not Applicable, not a new runtime prerequisite.

Fix uses two distinct comparison anchors:

1. For a previous Finding, origin is relative to the original reviewed change, not the repair diff. Preserve a supported original attribution with its evidence source. If a legacy report lacks attribution and the original comparison is unavailable, use Unknown; do not recast every old Finding as Retained merely because it existed before the fix.
2. For a New Regression, origin is relative to the fix baseline. Both New and Amplified are possible when the fix demonstrably introduces or worsens a defect. A merely retained, unrelated historical issue must not be mislabeled as a New Regression.

Keep the supplied IDs, original severities, and exactly one existing closure status. In reproduction evidence, distinguish pre-fix observations from post-fix verification; do not add their counts together. Origin uncertainty alone does not force closure to Cannot Verify when the original acceptance criteria can still be checked. Conversely, `0/N` alone does not satisfy closure when required runtime equivalence or another acceptance condition is missing.

Preserve Fix's focused scope. If an observation affects a previous Finding's acceptance, explain it in that item's remaining risk or verification. Unrelated historical defects require a separately selected scope, not an unsolicited Deep Review or hidden extra Findings under Evidence.

## Illustrative Fragments

These are proposed field examples, not actual Findings, full reports, observed repository results, or inputs for the stable report validator.

```md
- 问题来源：New：本次引入；相对本次比较基线，实时读取 session 改为初始化时缓存 token，登出后的清理行为因此丢失。
- 复现观测：Not Run：未执行；静态调用链支持触发条件，未执行浏览器或真实登录流程。

- 问题来源：Retained：历史遗留；该空值分支在比较基线中已存在，本次修改同一决策块但未修正它。
- 复现观测：Observed：已观测；同一 revision、相同初始状态的本地合成场景中观察到 2/3 次失败，记录见 Evidence；不能据此推断线上概率。

- 问题来源：Unknown：无法确定；旧报告无来源证据，原始变更基线不可读；本次修复基线仅用于验证闭环。
- 复现观测：[修复前] Observed：已观测；给定同版本 WebView 恢复场景记录为 1/1 次失败。 | [修复后] Cannot Verify：无法验证；缺少等价 WebView 环境，未得到有效修复后样本。
```

English output uses the same states and evidence meaning, for example: `Origin: Amplified - the fix adds a second caller to an already defective cache path; both baseline and new caller are evidenced.` A counterexample is `Reproduction: 1% probability, low risk` without representative data; a second is `Origin: New because this line changed` without a behavior comparison.

## Offline Acceptance Matrix

This remains a test-design matrix, not an authorized model-run sequence. Public synthetic source, raw observation records, output-field fragments, six authored bilingual reports and candidate-only checks are now prepared in the [offline prototype](evaluation-results/v0.6.0-origin-occurrence-prototype.md). Model workspaces are not prepared; evaluator answers stay outside any future model workspace.

| Case | Mode / input | Required judgment | Negative case |
| --- | --- | --- | --- |
| O-01 | Quick; a guard is removed and a reachable supported input now fails | New with baseline-to-current causal evidence; Not Run if static only | Infer runtime counts from static proof |
| O-02 | Quick; a modified decision block retains an old material defect | Retained, still independently reported in scope | Omit it or label it New because the block changed |
| O-03 | Deep; a new caller exposes an existing defect to a concrete additional input set | Amplified with the existing defect and changed exposure identified | Invent a percentage increase in production occurrence |
| O-04 | Quick; current defect is supported, original comparison is unavailable | Unknown origin with a named gap; severity follows demonstrated impact | Invent a baseline or use Unknown as severity |
| O-05 | Deep; a restrictive but supported state has a demonstrated canonical Blocking outcome | Report the evidenced defect without downgrading solely for rarity | Suppress it as an extreme case or invent frequency |
| O-06 | Quick; supplied equivalent synthetic trials have two failures and one success | Observed 2/3 with unit, environment, revision, and source | State 67% production probability or mix other environments |
| O-07 | Quick; a timing-sensitive path has zero failures in three valid trials | Observed 0/3; assess causal and contrary evidence without declaring universal safety | Automatically withdraw supported timing risk or claim a fix |
| O-08 | Quick; two valid trials and one setup failure | Count only the two valid trials; preserve the invalid attempt as a limitation | Count setup failure as a non-reproduction |
| O-09 | Fix; a previously New issue has supported attribution and a verified repair | Preserve original origin, ID and severity; report pre/post evidence separately; use normal closure criteria | Relabel Retained relative to the fix baseline or merge pre/post counts |
| O-10 | Fix; repair amplifies an existing defect on a directly affected path | New Regression with Amplified origin relative to the fix baseline and next unused ID | Hide the amplified regression as mere historical debt |
| O-11 | Fix; legacy report lacks origin but provides usable closure criteria | Unknown original origin; closure assessed independently from current repair evidence | Invent old attribution or automatically force Cannot Verify closure |
| O-12 | Quick; proven maintainability-only duplication | Existing Improve severity and optional recommendation; Not Applicable with reason | Introduce a runtime gate or a made-up failure rate |
| O-13 | Quick; correct behavior-preserving relocation with no material issue | Existing no-finding sections and Keep; no extra Finding or empty metadata section | Manufacture a New Finding from moved lines |
| O-14 | All; malformed/missing metadata, unsupported n/N, or unbacked percentages | Reject inconsistent candidate output; keep stable legacy validation distinct | Accept n > N, zero denominator, missing evidence, or confidence used as frequency |

O-07 must include a genuine refuting-evidence variant as well as a non-refuting small-sample variant. The former requires narrowing or withdrawing the unsupported claim; the latter must not be presented as universal safety. Include Chinese and English output counterparts, and a Fix case whose prior report has no stable IDs, preserving current legacy matching behavior.

## Boundaries And Risks

- Two new fields still add output cost; their purpose is clarity, not speculative accuracy or speed claims. Reuse existing evidence and permit concise gap states instead of mandatory new investigations.
- Source attribution can be wrong when baselines or contracts differ. Unknown with an explicit missing anchor is preferable to unjustified certainty, but must not conceal evidence that refutes the Finding itself.
- Small or selected samples create false precision. Record what was observed, its unit, and its limits; do not label a sample ratio as production probability.
- Fix attribution can drift to the repair baseline. Keep original attribution, current closure, and newly introduced regressions separate.
- A structural validator can accept semantically false explanations. Source-based adjudication and actual model trials remain required before any quality or release claim.
- This design does not add automatic fixes, a new review mode, mandatory telemetry, new MCP dependencies, a hosted service, framework-specific prompt forks, or a production-probability estimator.
